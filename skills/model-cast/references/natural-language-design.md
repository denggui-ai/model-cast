# 用自然语言设计人物

目标是让用户用日常语言控制人物方向，并能持续修改。不要把生图提示词、JSON、五官清单或内部状态变成用户表单。开始时读用户已有描述、已展示图片及反馈；只有确实缺少关键依据才补问。

## 从一句话形成可执行方向

用户可以说用途（“给通勤女装拍图”）、气质（“年轻、有点清冷”）、局部要求（“长发、精致妆容”），也可以只给一张喜欢的参考。先处理已有内容：

- 明确要求直接保留，包括不喜欢的地方。使用当前有效要求，后来的修改替换旧值；喜欢新参考不自动撤销此前的长发等要求。
- 从实际可见参考中描述外观；“这张更好看”只证明整体偏好，不能断言用户喜欢其中每一个五官。把自己提出的具体细化称为建议，不伪装成用户原话。
- 未说明的细节可留开放，或给一个与上下文一致的建议。不要为了填满字段自行固定肤色、国别、精确年龄、体型、眼形和唇形。
- 若用途会影响选角，可补问服饰品类与希望给顾客的感觉；没有商品图或客群资料也能先设计人物，匹配度暂不下结论。消费者年龄不等于模特年龄。

先用两三句普通话给出当前方向：**要怎样的人；哪些确定、哪些是建议；避免什么。** 身体只在相关时描述；只有脸照时，身材是未确定的目标。无需每轮把内部分类完整列给用户。

信息足够且已有生成授权，说明关键假设后继续。只有答案会改变人物身份、核心外观或参考用途时才澄清；一次集中解决最关键的歧义，不逐个盘问五官。用户要求“你推荐”“直接来一张”时给一个推荐方向并在授权内执行。若用户仍在探索、差异较大且没有偏好，可给两三个短方向供比较，不默认生成多张。

## 把感觉说清，避免固定审美模板

以下是解释方法，不是词语到五官的固定字典：

| 用户表达 | 如何落到这次人物上 |
|---|---|
| 年轻一点 | 结合上张图判断是成熟妆感还是面孔年龄感；保持成年。不把客户年龄直接写成模特年龄，也不悄悄指定精确岁数。 |
| 精致妆容 | 可以建议眉眼与唇妆更完整、边界干净，同时保留自然肤质；不能自动加大眼睛、抬高鼻梁或改变身份。浓淡有实质歧义时再澄清。 |
| 混血感、清冷、高级 | 用用户参考或给一个明确标为建议的视觉解释；不把词语固定映射为某种肤色、族群或标准脸，不从图片认定血统。 |
| 真人感 | 看表情、皮肤区域差异、眼神与发丝等是否自然；毛孔、雀斑和随机不对称不是必加项，不能用它们保证像真人。摄影质感不写成永久身份。 |
| 有辨识度 | 从已偏好的面孔提炼可记住的特征，或在开放创作时提出一两项建议；不靠随意加痣或夸大五官。是否换图仍认得需后续实图检验。 |
| 身材自然、丰满、运动感 | 写成可见体型目标，不自动变成细腰长腿或某个身高尺码；脸照不能验收这些目标。 |

参考图要按用户实际意图区分：

- **沿用这个人：**原图作身份依据，本次变更妆发等范围说清楚；图中衣服、背景和动作不自动变成身份要求。
- **喜欢这种感觉、另创一人：**提炼用户认可或明确标为建议的视觉特征。当前私人接口只支持身份附件，不能假称已有独立的审美参考槽；采用文字新建时不附旧脸，避免又锁回旧人。
- **还没选定：**保留为方向参考，不自动保存成已接受人物。用户已表明两种做法均可时，可推荐一个先行方向，无需重复追问二选一。

## 用反馈继续设计

每次修改用一句话说清**保留什么、改变什么**，再更新完整当前条件。已满意的部分沿用，不重新从零盘问；旧矛盾值从本次请求移除，历史版本保留。

- “脸可以，只把头发改长”：保持该脸，修改头发。妆容、年龄基准等未要求变化的部分沿用。
- “太成熟，想要年轻成年感”：未接受候选可重新选角，不能默认锁住首张脸；已接受身份则先分辨是妆发减龄还是换人物，明确换脸才另存新人版本。
- “不好看”“太假”：直接承认未达到期望；结合图指出可能的具体问题并推荐下一步，不把猜测当用户结论。用户已给满意例子时先用它推进，不再只问“哪里不好看”。
- “鼻子柔和些，其他不变”：按局部修改处理，说明会影响面孔；保留其他要求，实图仍要检查是否变成另一人。已保存人物另存候选，不覆盖旧包。

展示一张实际候选后，对照这轮要求指出做到和未做到的部分。按相关性看成年年龄感、妆发、真人感、辨识度和商品客群匹配；不机械给所有项目打分，不只问“满意吗”。用户自然语言的整体接受可以涵盖已展示范围，不强迫逐项签字。方向认可、生图授权和实际图像接受分别记录；“继续改”不等于接受上一张。

## 接到已有执行入口

设计结论交给 [private-workflow.md](private-workflow.md)，不新建解析器、评分系统或人物字段：

- 简报只保留任务需要的原话、当前要求、助手建议、未知项及修改范围，放在私人任务旁；文字咨询直接在回复中交付即可。
- 生成阶段 `model.locked` 承载本次要求保留的条件，并不表示图片已经实现；`adjustable` 承载用户允许变化的部分。已采用 factors 时沿用其 target／来源语义。业务背景留在简报，不塞入永久脸部字段。
- 原生请求应与最新简报一致；检查没有带回被替换的年龄、发型、脸或排除项。仅讨论方案时不 prepare、reserve 或生图。
- 接受后才保存，并核对真实接受范围。未接受旧候选作编辑参考时，按执行说明的零调用保存路径只保存实际采用的身份，不把被拒图固化进包。

## 对话示例

用户：“帮我做个年轻点、长发、妆容精致、有混血感的女模特。”

可回应：“先做一位年轻成年女性，长发，妆容完成度高，肤质保持自然。对你说的混血感，我建议先试较立体的眉眼搭配柔和轮廓；这是本次推荐，具体五官还留有空间。”有参考时优先结合参考，不默认这句话适合所有人；若只在讨论需求，到此交付文字即可。

用户：“这张脸可以，头发再长一点，别太浓妆。”

可回应：“保留这张的面孔和年龄感，把头发加长；妆容保留细致度，减淡眼线和唇色。其余人物要求沿用。”按实际授权决定是否生成，不重新询问已说明的条件。

用户：“不喜欢这张脸，之前那组三视图更好看。”

打开实际旧图，沿用其作为更受偏好的例子；未接受的新脸不再锁定。先提出如何利用旧图的简短方向，结合用户已说的“沿用人物／只借感觉”决定执行路径，不用新增候选掩盖尚未明确的方向。
