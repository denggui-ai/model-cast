# Face Casting：面部定妆设计指导

本指南用于帮助用户设计和调整原创成年虚拟模特的面部。它补充现有 C1–C8 / C11 流程，不替代阶段规格、固定提示词、Owner 审批或生图授权规则。

## 何时使用

仅当用户表达面部审美方向、要求比较面部特点、要求定妆调整，或对候选/定妆图提出面部修改意见时使用。用户没有提出面部设计需求时，不强行增加咨询轮次。

始终区分：
- **用户明确要求**：用户亲自表达的偏好和禁止项；
- **助手观察/建议**：从当前图像观察到的可见特点，必须标为建议；
- **未知/待确认**：图像或文字不足以可靠判断的内容。

不得把助手建议写成用户要求，也不得把推测写成事实。需要澄清时，只问一个最关键的问题。

## 八项设计原则

### 1. Signature Feature：核心记忆点

识别用户最希望保留的主要面部特征，可有辅助特征。可以是眼型、眉眼关系、鼻型、唇形或轮廓。用户未指定时，可以描述候选中可见的辨识特点作为建议，但不能擅自设为硬性偏好。不得默认杏眼，也不强制每张脸只有一个记忆点。

### 2. Facial Harmony：五官整体协调

不要孤立地追求某个五官更大、更挺或更厚。综合观察眼型/眼距/鼻宽、鼻底/唇部/下巴的视觉空间、颧骨至面颊至下颌的过渡，以及五官与脸部宽高和留白的关系。这是审美观察框架，不是自动美丑评分。

### 3. Independent Feature Attributes：独立属性拆分

将模糊修改拆成具体属性：
- 眼睛：形状、可见大小、眼距、眼睑开合、眼尾走向；
- 鼻子：鼻梁高度/宽度、鼻尖形态/投射/上翘程度、鼻翼宽度；
- 嘴唇：上唇厚度、下唇厚度、嘴角间水平宽度、唇峰；
- 下巴：长度、宽度、圆钝或尖锐程度；
- 脸型：面颊饱满度、颧部宽度、下颌宽度、轮廓过渡。

例如“嘴小一点”可能指唇厚，也可能指嘴宽。若上下文不能确定且不同解释会明显改变结果，只问一个关键问题；不要自行同时缩薄嘴唇并缩窄嘴宽。

### 4. Contour Transition：轮廓过渡

用户认为脸型生硬时，先观察颧骨—面颊—下颌—下巴之间的连接，再判断是否需要改变脸宽或下巴长度。轮廓形状、脸宽和下巴长度分开描述。

### 5. Shape Before Proportion：先形状后比例

完整设计一张脸时，先确定五官/轮廓形状，再检查协调关系，最后才考虑位置、间距和整体比例。用户只要求一个明确属性时，直接处理该属性，不强迫重走完整流程。三庭五眼等仅为观察参考，不是硬性标准。

### 6. Single-Objective Iteration：单一主要目标

每轮默认聚焦一个主要修改目标，并简要说明：
- **Change**：本轮主要改变什么；
- **Preserve**：已接受、应尽量保留什么；
- **Allowed coupling**：与目标直接相关、可能需要联动的部分；
- **Do not change**：与本轮无关、不应主动调整的部分。

用户明确要求同时修改多个目标时，不机械拒绝；说明联动风险，必要时建议拆轮，由用户决定。

### 7. Change Verification：检查实际变化

收到图像结果后，对照原图和本轮目标检查：目标是否实现、核心记忆点是否仍可辨认、保留项是否意外变化、整体协调性变化，以及局部纹理/边缘/过渡瑕疵。只报告实际可观察现象；无法确认时明确说不确定。

**Preserve 只是对图像模型的提示约束，不是像素级锁定，也不保证只编辑指定区域。** 不得仅凭提示词宣称身份保持成功。

### 8. Separate Visual Dimensions：分离视觉维度

默认分开处理面部几何、成年人物年龄表现、发型妆容、光线色彩、镜头角度/焦距/构图、表情视线和服装造型。诊断面部几何时，不同时改变灯光、镜头和妆发；用户明确要求组合变化时，说明难以归因的风险。

## 每轮修改的交互

1. 复述本轮主要目标；不重复整套理论。
2. 简要列出 Change / Preserve / Allowed coupling / Do not change。
3. 只有用户明确要求生成/编辑，且现有额度与授权闸门满足时，才按当前宿主的既有生图入口执行：Codex 宿主使用原生生图能力；Claude Code 宿主按项目 `SKILL.md` 使用 `codex exec`。不得因本指南改变宿主路由、调用次数、参考图传入或额度闸门。
4. 按现有项目规则显式指定参考图；不得假设上一轮结果自动成为参考图。
5. 返回图像后先检查，再报告实际观察；用户接受与技术验证是不同状态。
6. 用户接受的候选与原始图分开保存；绝不覆盖原始身份图。

## 失败与回退

- 目标未实现：说明未达到目标，分析是指令歧义还是编辑偏差，不得把未变化说成成功。
- 非目标区域明显变化：指出副作用；若影响核心记忆点，建议回到上一个已接受版本。
- 用户不喜欢：保留为未接受候选，回到上一个已接受版本重新规划。
- 用户连续改变方向：总结已确定偏好和新要求，只澄清真正冲突的关键点。
- 多属性修改难以归因：建议拆轮；用户坚持同时修改时，说明风险后按用户决定。
- 图片模糊、遮挡或角度不适合判断：标记无法判断，不编造比例或特征结论。
- 同一目标连续两次同类失败：遵守现有停止规则，保留证据并报告 Owner，不无限重试。

## 能力边界

本指南提供设计推理和提示组织，不提供人脸测量、自动审美评分、局部像素硬锁或绝对身份一致性保证。Eval 通过只证明指令/工作流行为符合预期，不证明实际图像质量；真实图像质量只能基于获授权生成的实际结果和用户验收判断。
