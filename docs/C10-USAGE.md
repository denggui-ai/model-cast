# C10 人物姿势线稿：使用规范与最小补充方案

**状态：** 三张灰色无脸人偶 PNG 与 SVG 源文件已加入本地补充分支；C10-01 有一次 ChatGPT 姿势执行记录，C10-02/03 尚未测试。
**范围：** 仅服务普通 ChatGPT / Codex 用户的可选人物动作参考；不属于 Lookset D2。

## 1. C10 解决什么问题

C10 只补充 C6 现有真实模特素材没有直接展示的身体姿势与肢体关系。它不是身份参考、不是服装线稿、不是商品图、不是编辑底图，也不替代真实模特照片。

参考职责必须分开：

| 参考资料 | 唯一职责 | 不负责 |
|---|---|---|
| C6 | 角色身份、脸部特征、身体比例及已有真实角度/动作 | 未展示动作的精确示范 |
| C10 | 身体姿势、四肢位置、关节关系、重心和动作方向；采用与 N2 一致的灰色无脸人偶视觉风格 | 身份、脸、发型、服装、商品细节 |
| N2 | 相机视点、拍摄方向、景别和裁切范围 | 人物身份、动作设计、服装 |
| 商品图 | 商品本身的颜色、款式、结构和细节 | 模特身份或人物姿势 |

## 2. 第一批最小集：3 张，而不是原计划 6 张

| 文件名建议 | 姿势 | 选择理由 | 与 C6 的差异 |
|---|---|---|---|
| `C10-01-Walk-Side.png` | 全身侧面行走 | 补充步态、前后腿关系和手臂摆动 | C6 有正面行走，没有直接对应的侧面行走 |
| `C10-02-Sit-Side.png` | 全身侧面坐姿 | 表达躯干倾角、髋膝弯曲和腿部前后关系 | C6 有正面坐姿，没有直接对应的侧面坐姿 |
| `C10-03-Hands-In-Pockets.png` | 正面或轻微 3/4 站姿，双手置于髋侧呈插兜手位（不画口袋结构） | 补充手臂位置、肩部状态和站姿重心 | C6 的站姿素材没有直接示范插兜 |

本批不做叉腰、回头、倚靠。它们保留为候选，不因原蓝图列出就自动扩展数量。三张使用后若没有可证明的实际收益，不继续扩展。

## 3. C10 人偶资产要求

- 一张图只表达一种姿势；单人、全身、完整显示头部至双脚。
- 采用与 N2 相同的灰色无脸、无发型、无服装人偶风格，使用干净的白色背景。
- 使用通用成年人体比例；不绘制可识别面孔、发型、首饰、服装款式、面料、缝线或商品细节。
- 重点表达头/躯干朝向、肩胯关系、肘膝弯曲、手脚位置、重心和动作方向。
- 不加入镜头箭头、景别标签、文字说明或装饰元素；文件名和索引承担标签职责。
- 三张保持一致的灰色材质、光照、人体比例、背景和画布比例；与 N2 的视觉风格一致。
- C10 只作姿势提示，不应要求生成结果复制 C10 人偶的体型或身体比例；人物身份和身体比例以 C6 为准。

## 4. N2：灰色人偶还是白模

**决定：现阶段保留现有灰色 N2，并让 C10 复用同一灰色人偶视觉体系，不制作黑色线稿或白模平行版本。**

理由：

1. 现有 N2 是灰色无脸人偶置于白色背景，12 个角度/景别已完成自检。
2. N2 负责相机视点和取景；C10 负责动作和关节姿势。两者职责不同，但统一人偶材质能降低用户理解成本。
3. 再制作黑色线稿或白模，会增加视觉风格数量，却不会增加新的功能职责。
4. 所以保留 N2 原图，只为 C10 增加三种 N2 未覆盖的动作姿势。

暂不制作白模，也不改变现有 N2 的 12 张图。

## 5. 实际使用：按任务选择，不默认全传

### 普通任务

使用 C6 最少身份参考（通常 01 正脸 + 04 正面全身，必要时加最相关角度图）及商品图。无需 C10 或 N2。

### 任务需要 C6 没有的姿势

选择一张 C10，与身份参考及商品图一起提供：

- 身份：C6 01 + 04（或任务最相关的已接受角度图）。
- 姿势：只选对应的一张 C10。
- 商品：用户实际商品图。
- 相机：只有视点或景别仍不明确时才增加一张 N2。

### N2 与 C10 同时使用

- C10 是姿势和肢体关系的权威参考。
- N2 只用于相机方向/景别/裁切，不重新定义人物动作。
- 若两张图表达的朝向冲突，以用户明确文字为准；姿势以 C10 为准；相机/裁切以 N2 为准。无法消解冲突时先询问，不要让图像工具自行猜测。
- 若 C10 自身已经清楚表达所需视角和构图，不再附加 N2。

## 6. ChatGPT / Codex 的附件边界

- AI 能读取资料库、识别文件或在文本中选中某张图片，不代表图像生成/编辑工具实际收到该图片作为参考。
- ChatGPT 用户：如果图像工具没有明确收到所选 C6/C10/N2 图片，应提示用户将被选中的原图文件单独补传；不能声称已经使用未传递的附件。
- Codex 用户：目前多文件本地文件夹到图像工具的端到端传递仍未验证。应显式提供身份图、所需 C10 线稿和商品图；不要依赖自动从文件夹选图并隐式传递。
- 每次任务只传最少必要参考，不要一次把全部 C6、三张 C10、N2 和商品图都塞给图像工具。

## 7. 服装与下游生成责任边界

`model-cast` 负责创建人物身份资料、姿势参考和清晰的参考交付说明；它不负责生成最终商品图，也不保证下游模型的服装还原质量。

- 商品图由用户提供，作为独立的商品参考输入。
- 使用说明可以要求下游 AI 尽可能参考商品图中的颜色、领口、拉链、袖口和整体轮廓。
- 商品细节是否准确、图像是否达到商业摄影标准，取决于下游图像工具和用户工作流，不属于 `model-cast` 的质量承诺。
- 示例生成只用于说明参考组合如何使用，不作为商品还原率或服装保真度的证明。

## 8. 资料包与边界

- C10 生成并验收后，作为独立可选目录 `5_C10_Pose_Guides/` 交付；索引标注 `pose-supplement`，明确“非身份参考/非服装图/非编辑底图”。
- 不覆盖现有 V3.0 中文包、英文包或任何旧候选。若要整合进正式卖家包，另建新版本候选并单独校验。
- 不进入 Lookset D2；不改变其 reference、supplements 或 `model.json` 契约。
- 当前 v0.2.0 正式 Release 不包含 C10。后续 C10 是独立补充，不回改或重打 v0.2.0。

## 9. 最简验收标准

只保留三项检查：

1. **线稿本身：** 三张姿势是否完整、清楚、容易理解，且没有身份或服装细节暗示。
2. **参考组合：** 一次真实任务中，C6 是否用于身份、C10 是否用于姿势，AI 是否理解两者职责。
3. **资料传递：** 所选图片是否真正传递给下游图像工具，而不只是被文本识别或提及。

服装仅作为组合使用示例，不单独设置商品还原率、细节准确率或商业摄影质量指标。
